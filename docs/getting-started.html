Getting started

Build the demo, run it, and understand what it does — one line at a time.

Building on your platform

The engine uses a plain Makefile. It figures out which platform you're on and pulls in the right sub-makefile. External dependencies get downloaded automatically the first time.

Windows

Needs clang and Visual Studio (for the linker). Vulkan headers, glslang, and FreeType are fetched automatically on first build.

make

macOS

Needs Xcode command-line tools. Uses the system Cocoa, Metal, and QuartzCore frameworks — nothing to download.

make

Web

The Emscripten SDK gets cloned and set up automatically. First build is slow (SDK install); subsequent builds are fast.

make PLATFORM=web
💡 Tip

Add SANITIZE=1 to enable AddressSanitizer for catching memory bugs during development. make test builds a separate test window and runs the buffer test suite.

The demo: a spinning triangle

The entire demo lives in src/main.c. It draws one triangle that rotates each frame. Let's walk through the whole thing.

Five steps to draw something. That's the whole engine's setup shape.

Step 1 & 2 — App and window

NEApp *app = ne_app_create();

NEWindow *window = ne_window_create(app, &(NEWindowDesc){
    .width  = 800,
    .height = 600,
    .title  = "NanoEngine",
    .undecorated = true,   // no native title bar
    .transparent = true,   // per-pixel alpha
});
The app is the connection to the operating system's event system. The window is a chunk of screen space. You can have many windows per app.

Step 3 — Renderer and surface

NERenderer *renderer = ne_renderer_create(&(NERendererDesc){
    .enable_validation = true,   // extra safety checks in debug builds
});

NERenderSurface *surface = ne_renderer_create_surface(renderer, window,
    &(NERenderSurfaceDesc){
        .vsync = true,
        .present_backend = NE_PRESENT_BACKEND_DXGI,  // for transparency
    });
The renderer is a single "connection to the graphics card". A surface is the marriage of one renderer with one window — it's where pixels actually appear.
On Windows: WSI vs DXGI

The demo picks NE_PRESENT_BACKEND_DXGI. That routes the final image through Windows' own compositor, which lets the window have real per-pixel transparency. If you don't need that, use NE_PRESENT_BACKEND_VULKAN_WSI (or leave the field at its default) — it's the standard path and slightly simpler.

See The swapchain for the full comparison.

Step 4 — Shaders and pipeline

// Read pre-compiled SPIR-V from disk (paths are baked in at build time)
size_t vert_size, frag_size;
void *vert_spv = ne_file_read(NE_SPIRV_VERT_PATH, &vert_size);
void *frag_spv = ne_file_read(NE_SPIRV_FRAG_PATH, &frag_size);

NEShaderHandle vs = ne_shader_create(renderer, &(NEShaderDesc){
    .stage = NE_SHADER_STAGE_VERTEX,
    .bytecode = vert_spv, .bytecode_size = vert_size,
    .entry_point = "main",
});
NEShaderHandle fs = ne_shader_create(renderer, &(NEShaderDesc){
    .stage = NE_SHADER_STAGE_FRAGMENT,
    .bytecode = frag_spv, .bytecode_size = frag_size,
    .entry_point = "main",
});

NEPipelineHandle pipeline = ne_pipeline_create(renderer, &(NEPipelineDesc){
    .vertex_shader   = vs,
    .fragment_shader = fs,
    .vertex_bindings = /* one binding, two attributes: position + color */,
    .topology        = NE_TOPOLOGY_TRIANGLE_LIST,
});
A shader is a small program that runs on the graphics card. A pipeline bundles a vertex shader, a fragment shader, and everything about how vertices are arranged in memory. You'll bind one pipeline per draw call.

Step 5 — The frame callback

// A "dynamic" vertex buffer — we'll rewrite its contents every frame
NEBufferHandle vbo = ne_buffer_create(renderer, &(NEBufferDesc){
    .size = sizeof(triangle_verts),
    .usage = NE_BUFFER_USAGE_VERTEX,
    .initial_data = triangle_verts,
    .dynamic = true,   // enables the fast per-frame-update path
});

// Bundle everything the frame callback will need
NEFrameContext frame_ctx = {
    .renderer     = renderer,
    .surface      = surface,
    .pipeline     = pipeline,
    .vertex_buffer = vbo,
    .vertex_count = 3,
    .on_update    = on_frame_update,   // called every frame
    .user_data    = &demo_state,       // rotation angle, etc.
};

// Register the callback with the window
ne_set_window_render_dispatch(window, ne_render_frame, &frame_ctx);

// Blocks until the window is closed
ne_app_run(app);

The per-frame update

static void on_frame_update(NEFrameContext *ctx, NERenderPass *pass) {
    DemoState *state = ctx->user_data;
    state->angle += 0.02f;

    // Rotate the triangle's vertices on the CPU
    Vertex rotated[3];
    for (int i = 0; i < 3; i++) {
        rotated[i].x = triangle[i].x * cosf(state->angle) - triangle[i].y * sinf(state->angle);
        rotated[i].y = triangle[i].x * sinf(state->angle) + triangle[i].y * cosf(state->angle);
        rotated[i].color = triangle[i].color;
    }

    // Push the new data into this frame's copy of the dynamic buffer
    ne_render_pass_update_buffer(pass, ctx->vertex_buffer, rotated, sizeof(rotated), 0);
}
Every frame, the engine calls this function. We compute rotated vertex positions on the CPU and hand them to the GPU. Because the buffer was created with dynamic = true, the engine keeps two separate copies internally — one for the frame the CPU is preparing, one for the frame the GPU is still drawing — so nothing gets stomped on.
How this could be better

The rotation is done on the CPU and re-uploaded every frame. For a triangle it's fine, but scaled up it wastes bandwidth. The better approach:

  • Keep the triangle vertices static (upload once, never again).
  • Pass the rotation angle to the vertex shader as a push constant (a tiny piece of data attached to the draw command).
  • Let the GPU do the rotation math on its own hardware.

The engine already supports push constants via ne_render_pass_set_uniform_data. The demo just uses the dynamic-buffer path to demonstrate that path exists.

Running it

./build/nano_engine     # on Windows / macOS
# or open build/index.html in a browser for the web build

You should see a borderless window with a rotating multicolored triangle. Press Esc or close the window to quit.
