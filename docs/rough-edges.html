Rough edges

The engine is small and works, but it isn't polished. This page lists the known issues, inconsistencies, and gaps — so nothing surprises you.

Inconsistencies

🐛 ne_renderer_create signature disagrees across backends

The public header declares:

NERenderer *ne_renderer_create(const NERendererDesc *desc);

But the Metal and WebGPU backends implement:

NERenderer *ne_renderer_create(NEApp *app, const NERendererDesc *desc);

The main.c demo happens to work because it uses the header's signature and compiles against the Vulkan backend. Fix: unify on one form (probably drop the NEApp arg since the renderer is a singleton).

🐛 NEImageHandle breaks the handle convention

Every other handle is:

typedef struct NEBufferHandle { uint32_t id; } NEBufferHandle;

But images are:

typedef uint64_t NEImageHandle;

Just make it struct { uint32_t id; } like the rest.

⚠️ ne_handle.h is empty

Reserved but never used. Per-resource handles are declared inline in each resource header. Either delete the file or actually put the shared handle machinery in it.

⚠️ Metal doesn't use NEPool

Vulkan and WebGPU share the pool from ne_alloc.h. Metal duplicates the concept with hand-rolled T*/count/cap fields. Refactor to unify.

Architectural gaps

No GPU memory allocator

Every buffer/image calls vkAllocateMemory directly. Real hardware caps allocations at ~4096. Fine for the demo, blocks any real scene.

Single GPU queue

Graphics + present + transfer all share one queue. Uploads serialize with draws. A dedicated transfer queue would parallelize.

Immediate destruction

Destroying a resource issues vkDeviceWaitIdle — stalls the whole GPU. Should be deferred until the GPU has moved past this frame.

Three shader languages

GLSL for Vulkan, MSL for Metal, WGSL for WebGPU. Every shader gets rewritten three times. Slang or SPIRV-Cross would collapse this.

No hot-reload

Shaders need a restart to pick up changes. A file watcher + hot re-link path would speed iteration a lot.

No generational handles

Destroy → new resource in same slot → old handle "works" but points somewhere new. A generation counter in the high bits would fix this.

Contributing back

The engine is deliberately small — most of these gaps are pretty tractable one-weekend projects. If you want to help, start with:

  1. Metal image API — the biggest single omission on that backend.
  2. WebGPU push-constant emulation — unblocks the biggest cross-backend semantic gap.
  3. GPU memory allocator — integrate VMA or roll a slab allocator.
  4. Descriptor sets — needed for any real uniforms/textures.
  5. Deferred destruction — replace the vkDeviceWaitIdle stalls.
