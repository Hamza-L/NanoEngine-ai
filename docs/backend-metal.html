Metal backend

1180 lines of Objective-C in one file. Simpler than the Vulkan backend because Metal makes a lot of decisions for you.

Why Metal is simpler than Vulkan

The whole backend fits in src/renderer/metal/ne_renderer_metal.m — one file. Compare to Vulkan's seven. This isn't laziness; Metal genuinely does more for you:

No function loader

Metal is part of macOS. You link the framework and every function is there.

No queue families

One MTLCommandQueue for everything. No enumeration, no picking.

Unified memory on Apple Silicon

CPU and GPU share the same memory. No staging buffer, no copy commands.

Auto-tracked resources

Metal tracks which resources a command buffer references and keeps them alive automatically.

The renderer struct

// src/renderer/metal/ne_renderer_metal.m
struct NERenderer {
    void *device;    // id<MTLDevice>        (ARC-retained via CFBridgingRetain)
    void *queue;     // id<MTLCommandQueue>

    NEShaderSlot   *shaders;    uint32_t shader_count;   uint32_t shader_cap;
    NEBufferSlot   *buffers;    uint32_t buffer_count;   uint32_t buffer_cap;
    NEPipelineSlot *pipelines;  uint32_t pipeline_count; uint32_t pipeline_cap;

    NEShaderOptimization shader_optimization;
};
🐛 The pools don't use NEPool

Unlike Vulkan and WebGPU, this backend uses a hand-rolled pool (T* + count + cap) instead of the shared NEPool from ne_alloc.h. The allocator still scans linearly for a free slot; the API just isn't unified. Something to clean up.

The surface struct

struct NERenderSurface {
    NERenderer *renderer;
    NEWindow   *window;

    void *layer;             // CAMetalLayer*  — the actual swapchain
    void *drawable;          // id<CAMetalDrawable>  — this frame's image
    void *command_buffer;    // id<MTLCommandBuffer>
    void *encoder;           // id<MTLRenderCommandEncoder>  — open during frame

    float clear_color[4];

    dispatch_semaphore_t frame_semaphore;    // CPU/GPU pacing (init = 2)
    uint32_t frame_index;                    // ring 0..1

    NERenderPass pass;                       // embedded, per-surface

    // Per-frame pass state
    uint32_t         current_topology;
    NEBufferHandle   current_index_buffer;
    uint32_t         current_index_type;
};
💡 Each surface has its own NERenderPass

Unlike the WebGPU backend (which has a single global pass), each Metal surface embeds its own pass token. That means N surfaces can render on independent timelines — one window can draw while another finishes its previous frame.

Boot sequence

All of five steps. Compare to Vulkan's ten.

NERenderer *ne_renderer_create(const NERendererDesc *desc) {
    // 1. Get the system's default GPU
    id<MTLDevice> device = MTLCreateSystemDefaultDevice();
    if (!device) return NULL;

    // 2. Create the one and only command queue
    id<MTLCommandQueue> queue = [device newCommandQueue];

    // 3. Allocate the renderer struct
    NERenderer *r = calloc(1, sizeof(NERenderer));

    // 4. Hand ownership of the ObjC objects into the struct's void* fields
    r->device = (__bridge_retained void *)device;
    r->queue  = (__bridge_retained void *)queue;

    // 5. Done. (Note: enable_validation is ignored — see below.)
    return r;
}
⚠️ enable_validation is silently ignored

Metal's GPU validation isn't a runtime device flag — it's an environment variable (MTL_DEBUG_LAYER=1) or an Xcode scheme setting. The engine documents this in a comment but the field is a no-op on this backend.

Frame loop

Metal frames are shorter and less ceremonious than Vulkan frames. The command encoder does the heavy lifting.

NERenderPass *ne_renderer_begin_frame(NERenderer *r, NERenderSurface *s) {
    // Guard: refuse if already in a frame (per-surface, not global)
    if (s->drawable || s->command_buffer) return NULL;

    // 1. Block if 2 frames are already in flight
    dispatch_semaphore_wait(s->frame_semaphore, DISPATCH_TIME_FOREVER);

    // 2. Resize handling — cheap, done every frame
    int32_t fb_w, fb_h;
    ne_window_get_framebuffer_size(s->window, &fb_w, &fb_h);
    CAMetalLayer *layer = (__bridge CAMetalLayer *)s->layer;
    layer.drawableSize = CGSizeMake(fb_w, fb_h);

    // 3. Get the next drawable image
    id<CAMetalDrawable> drawable = [layer nextDrawable];
    if (!drawable) {
        // May happen during resize or when window is occluded
        dispatch_semaphore_signal(s->frame_semaphore);
        return NULL;
    }

    // 4. Make a command buffer for this frame
    id<MTLCommandQueue> queue = (__bridge id<MTLCommandQueue>)r->queue;
    id<MTLCommandBuffer> cmd = [queue commandBuffer];

    // 5. Set up the render pass descriptor
    MTLRenderPassDescriptor *rpd = [MTLRenderPassDescriptor renderPassDescriptor];
    rpd.colorAttachments[0].texture     = drawable.texture;
    rpd.colorAttachments[0].loadAction  = MTLLoadActionClear;
    rpd.colorAttachments[0].storeAction = MTLStoreActionStore;
    rpd.colorAttachments[0].clearColor  = MTLClearColorMake(s->clear_color[0], ...);

    // 6. Open a render command encoder — this stays open until end_frame
    id<MTLRenderCommandEncoder> enc = [cmd renderCommandEncoderWithDescriptor:rpd];

    // 7. Full-viewport by default
    [enc setViewport:(MTLViewport){0, 0, fb_w, fb_h, 0, 1}];
    [enc setScissorRect:(MTLScissorRect){0, 0, fb_w, fb_h}];

    // 8. Store into the surface + return the pass token
    s->drawable       = (__bridge_retained void *)drawable;
    s->command_buffer = (__bridge_retained void *)cmd;
    s->encoder        = (__bridge_retained void *)enc;
    s->frame_index    = (s->frame_index + 1) % 2;
    return &s->pass;
}
void ne_renderer_end_frame(NERenderer *r, NERenderSurface *s) {
    // Close the encoder — this is where the command buffer is finalized
    [(__bridge id<MTLRenderCommandEncoder>)s->encoder endEncoding];

    // Register a completion handler that signals our semaphore
    // → this is what un-blocks begin_frame's semaphore_wait next frame
    id<MTLCommandBuffer> cmd = (__bridge_transfer id<MTLCommandBuffer>)s->command_buffer;
    dispatch_semaphore_t sem = s->frame_semaphore;
    [cmd addCompletedHandler:^(id<MTLCommandBuffer> _){ dispatch_semaphore_signal(sem); }];

    // Schedule presentation on the next display refresh
    id<CAMetalDrawable> drawable = (__bridge_transfer id<CAMetalDrawable>)s->drawable;
    [cmd presentDrawable:drawable];

    // Send everything to the GPU
    [cmd commit];

    s->encoder = s->drawable = s->command_buffer = NULL;
}

Sync — the semaphore, not fences

One dispatch_semaphore_t per surface, initialized to 2. Each begin decrements, each GPU completion increments.
A dispatch semaphore is macOS's version of a counting semaphore. It has a count. Take one → count goes down. Release one → count goes up. If the count is 0 and you try to take, you block. That's it.

Buffers — no staging, no copy commands

Apple Silicon has unified memory: the CPU and GPU physically share the same DRAM. There's no notion of "video RAM" — it's all just RAM. This lets the backend skip the whole staging-buffer dance.

// Everything uses MTLResourceStorageModeShared
buffer = [device newBufferWithLength:size options:MTLResourceStorageModeShared];

// Update = plain memcpy into a persistently-mapped pointer
memcpy((uint8_t *)[buffer contents] + offset, data, size);

Dynamic buffers still allocate 2 copies (one per in-flight frame), but static buffers allocate only 1. There's no "static vs. staging vs. dynamic" three-way path like Vulkan has — just "shared, always".

⚠️ Intel Mac support was dropped

Discrete GPUs (which macOS supports on older Intel Macs) can't use Shared storage for GPU-fast reads. The backend intentionally targets Apple Silicon only. Adding Intel support would need StorageModeManaged + didModifyRange:.

Shaders — MSL, not SPIR-V

Metal doesn't accept SPIR-V. You give it either MSL source (Metal Shading Language, a C++ dialect) or a precompiled metallib blob.

// Path 1: pre-compiled metallib
NSError *err = nil;
id<MTLLibrary> lib = [device newLibraryWithData:data error:&err];
id<MTLFunction> fn = [lib newFunctionWithName:@"vertex_main"];

// Path 2: source (via ne_shader_create_from_source)
id<MTLLibrary> lib = [device newLibraryWithSource:msl_source
                                          options:opts
                                            error:&err];
💡 Future path: Slang

The current split (GLSL on Vulkan, WGSL on Web, MSL on Metal) means you write three copies of every shader. A comment in the code hints at a future Slang integration that would transpile one source into all three targets.

Push constants — Metal calls them "bytes"

Metal has native inline uniforms and generously allows up to 4 KB — 32× what Vulkan guarantees.

// From ne_render_pass_set_uniform_data
[enc setVertexBytes:data length:size atIndex:slot];
// or
[enc setFragmentBytes:data length:size atIndex:slot];

The engine still caps at 128 bytes to match the public API's Vulkan-derived limit — but internally there's tons of room.

Pipelines — eager compilation

Unlike Vulkan (where compile is deferred until the render pass is known), Metal knows everything it needs at pipeline creation. So compilation is synchronous inside ne_pipeline_create:

MTLRenderPipelineDescriptor *pd = [MTLRenderPipelineDescriptor new];
pd.vertexFunction   = vertex_fn;
pd.fragmentFunction = fragment_fn;
pd.colorAttachments[0].pixelFormat = MTLPixelFormatBGRA8Unorm;

// Optional blend state
if (desc->blend.enabled) {
    pd.colorAttachments[0].blendingEnabled = YES;
    // ... blend factors, ops ...
}

// Vertex layout
MTLVertexDescriptor *vd = [MTLVertexDescriptor new];
for (uint32_t i = 0; i < desc->vertex_binding_count; i++) { /* fill in */ }
pd.vertexDescriptor = vd;

// Compile — synchronous, may take a millisecond
id<MTLRenderPipelineState> pso = [device newRenderPipelineStateWithDescriptor:pd
                                                                       error:&err];
⚠️ Topology is stored separately

Vulkan bakes topology (triangles vs lines vs points) into the pipeline. Metal doesn't — you pass it at draw time. The engine stores it on the slot and applies it in ne_render_pass_draw.

Present — via CAMetalLayer

// Layer setup at surface-create time
CAMetalLayer *layer = [CAMetalLayer layer];
layer.device      = device;
layer.pixelFormat = MTLPixelFormatBGRA8Unorm;

if (ne_window_is_opaque(window)) {
    layer.framebufferOnly = YES;   // faster
    layer.opaque = YES;
} else {
    layer.framebufferOnly = NO;    // required for transparency
    layer.opaque = NO;
}

if ([layer respondsToSelector:@selector(setDisplaySyncEnabled:)]) {
    layer.displaySyncEnabled = desc->vsync ? YES : NO;
}

// Attach to the window's NSView
[view setWantsLayer:YES];
view.layer = layer;

What's missing

FeatureStatus
Image API (ne_image_*)❌ Missing entirely — no textures
Compute pipelines & passes❌ Stubs, log warnings
Depth/stencil attachment❌ Only color[0] wired up
enable_validation flag❌ Ignored (env-var-driven in Metal)
Library cache❌ Every shader rebuilds an MTLLibrary
Intel Mac / discrete GPU path❌ Intentional (Apple Silicon only)
How this could be better
  • Add textures. The image API is completely missing — probably the highest-impact gap.
  • Unify with NEPool. The hand-rolled pool duplicates functionality that already exists in ne_alloc.h. Straightforward refactor.
  • Cache MTLLibrary objects. A hash-keyed cache would let identical shader source reuse compiled libraries.
  • Wire up depth. Currently 2D-only.
  • iOS / tvOS support. The Metal API is the same; only the window/view creation would need alternates.
