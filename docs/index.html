NanoEngine

A small engine that draws pictures on your screen. It runs on Windows, macOS, and inside a web browser — with the same code you write once.

Windows macOS Web   Vulkan Metal WebGPU

What is it?

NanoEngine is roughly 10,000 lines of C code that gives you three things:

  1. A window — on any of the three platforms above.
  2. A way to talk to the graphics card — buffers of vertices, shaders that draw them, pipelines that stitch it all together.
  3. A frame loop — the heartbeat that pushes one picture to the screen after another.

The interesting part is the portability. On Windows, the engine talks to the graphics card through Vulkan. On macOS, Metal. In a browser, WebGPU. Your code doesn't change — the engine picks the right one at build time.

One public API on top. The build system picks exactly one backend to compile.
Think of the public API as a light switch on the wall. On Windows, the wire behind it goes to Vulkan. On macOS, it goes to Metal. In a browser, it goes to WebGPU. Same switch, different wiring.

What can you do with it today?

Open a window

Borderless, dark-mode, DPI-aware. Custom title bar on Windows. Cocoa-native on macOS. HTML canvas on the web.

Draw a triangle

Static or animated. With per-frame updates through a special kind of buffer that avoids copies.

Load shaders

Pre-compiled bytecode for shipping, or plain GLSL text — the engine compiles it at startup.

Transparent windows

On Windows, an optional DXGI + DirectComposition path lets you present through Windows' own compositor for per-pixel alpha.

How the code is organized

The full project tree is about 30 files. The important shape:

NanoEngine/
├── include/              ← The public API. Platform-neutral.
│   ├── ne_app.h              App lifecycle (start/stop)
│   ├── ne_window.h           Windows & input events
│   ├── ne_renderer.h         Renderer & surfaces
│   ├── ne_renderer_buffer.h  GPU memory
│   ├── ne_renderer_shader.h  Shaders
│   ├── ne_renderer_pipeline.h  Pipelines (drawing "recipes")
│   └── ne_renderer_pass.h    Drawing commands
│
├── src/
│   ├── main.c                Demo — a spinning triangle
│   ├── platform/
│   │   ├── win32/            Windows implementation
│   │   ├── macos/            macOS implementation
│   │   └── web/              Browser implementation
│   └── renderer/
│       ├── vulkan/           Windows backend (biggest)
│       ├── metal/            macOS backend
│       └── wgpu/             Web backend
│
├── shaders/               GLSL and WGSL source
└── Makefile               Chooses which backend to build

The rest of this documentation walks through each piece — starting with the big picture (the four layers), then zooming into the details.
