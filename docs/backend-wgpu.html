WebGPU backend

1175 lines of C compiled with Emscripten. The interesting part is what runs where — a lot of the "engine" is actually inside your browser.

What's WebGPU?

WebGPU is a graphics API for the web. It's designed to look like Vulkan/Metal/D3D12 but be safe enough to run untrusted code from any website. Under the hood, your browser (Chrome, Safari, Firefox) implements it on top of the native API — Vulkan on Linux, Metal on Mac, D3D12 on Windows.

Your C code, compiled to WebAssembly, talks to the browser's WebGPU implementation, which talks to the real graphics driver.

The renderer struct

// src/renderer/wgpu/ne_renderer_wgpu.c
struct NERenderer {
    WGPUInstance instance;
    WGPUAdapter  adapter;
    WGPUDevice   device;
    WGPUQueue    queue;

    bool device_ready;    // set true once async device setup completes
    bool device_failed;

    NEPool shaders;       // uses the shared ne_alloc.h pool
    NEPool buffers;
    NEPool pipelines;

    WGPUTextureFormat surface_format;   // chosen lazily on first frame

    NEShaderOptimization shader_optimization;   // stored but unused
};
💡 Uses the shared NEPool

This backend does the pool-based storage properly, sharing ne_alloc.h with the Vulkan backend. And unlike the Metal backend, it also calls ne_pool_free — freed slots are actually reused.

The wrinkle: async device setup

Getting a Vulkan or Metal device is synchronous. On WebGPU, it's asynchronous — the browser has to ask the user for GPU access, negotiate features, and it all happens through callbacks.

NERenderer *ne_renderer_create(const NERendererDesc *desc) {
    NERenderer *r = calloc(1, sizeof(NERenderer));
    r->instance = wgpuCreateInstance(NULL);

    // Kick off adapter request — returns immediately, callback fires later
    wgpuInstanceRequestAdapter(r->instance, &opts, (WGPURequestAdapterCallbackInfo){
        .mode = WGPUCallbackMode_AllowSpontaneous,
        .callback = ne_wgpu_on_adapter,
        .userdata1 = r,
    });

    // Return NOW with device_ready = false
    return r;
}

// Fires later:
static void ne_wgpu_on_adapter(status, adapter, msg, r, _) {
    r->adapter = adapter;
    // Chain: adapter → device
    wgpuAdapterRequestDevice(adapter, &device_desc, /* callback */ ...);
}

// Fires later still:
static void ne_wgpu_on_device(status, device, msg, r, _) {
    r->device = device;
    r->queue = wgpuDeviceGetQueue(device);
    r->device_ready = true;   // ← finally usable
}
Every resource-create call gates on device_ready. It's the biggest structural difference from the other backends.
⚠️ Callers must tolerate NULL returns during startup

The demo doesn't currently handle this well — it just tries to create shaders/pipelines during setup, which return null. Real apps on this backend would need to queue setup work until device_ready.

The surface struct

struct NERenderSurface {
    NERenderer *renderer;
    NEWindow   *window;

    WGPUSurface surface;
    char *canvas_selector;      // strdup'd, e.g. "#canvas"

    bool     configured;
    int32_t  configured_w;
    int32_t  configured_h;

    float clear_color[4];
    uint32_t frame_index;       // 0..2 (three frames in flight)

    // Per-frame encoders
    WGPUCommandEncoder    encoder;
    WGPURenderPassEncoder pass_encoder;
    WGPUTextureView       view;
    WGPUTexture           texture;

    // Pass state
    WGPUPrimitiveTopology current_topology;
    NEBufferHandle        current_index_buffer;
    WGPUIndexFormat       current_index_format;
};
🐛 Single global active pass

Unlike Metal (per-surface pass) or Vulkan (per-surface pass), this backend uses a single static NERenderPass g_active_pass. That means only one surface can be mid-frame at a time. Multi-window rendering on the web is limited.

Frame loop — no explicit present

NERenderPass *ne_renderer_begin_frame(NERenderer *r, NERenderSurface *s) {
    if (r->device_failed || !r->device_ready) return NULL;
    if (g_active_pass.surface) return NULL;   // global re-entry guard

    // 1. Get current framebuffer size (canvas × device-pixel-ratio)
    int32_t w, h;
    ne_window_get_framebuffer_size(s->window, &w, &h);

    // 2. Lazily pick the surface format on first frame
    if (r->surface_format == WGPUTextureFormat_Undefined) {
        WGPUSurfaceCapabilities caps;
        wgpuSurfaceGetCapabilities(s->surface, r->adapter, &caps);
        r->surface_format = caps.formats[0];
        wgpuSurfaceCapabilitiesFreeMembers(caps);
    }

    // 3. Re-configure the surface on size change
    if (!s->configured || s->configured_w != w || s->configured_h != h) {
        WGPUSurfaceConfiguration cfg = {
            .device = r->device,
            .format = r->surface_format,
            .usage  = WGPUTextureUsage_RenderAttachment,
            .width = w, .height = h,
            .presentMode = WGPUPresentMode_Fifo,
            .alphaMode   = WGPUCompositeAlphaMode_Auto,
        };
        wgpuSurfaceConfigure(s->surface, &cfg);
        s->configured = true;
        s->configured_w = w; s->configured_h = h;
    }

    // 4. Acquire the current texture (skip on suboptimal)
    WGPUSurfaceTexture st;
    wgpuSurfaceGetCurrentTexture(s->surface, &st);
    if (st.status != SuccessOptimal && st.status != SuccessSuboptimal) return NULL;

    // 5. Command encoder → begin render pass
    s->texture = st.texture;
    s->view = wgpuTextureCreateView(st.texture, NULL);
    s->encoder = wgpuDeviceCreateCommandEncoder(r->device, NULL);

    WGPURenderPassColorAttachment color = {
        .view = s->view,
        .loadOp = WGPULoadOp_Clear,
        .storeOp = WGPUStoreOp_Store,
        .clearValue = { s->clear_color[0], /* ... */ },
    };
    s->pass_encoder = wgpuCommandEncoderBeginRenderPass(s->encoder, &(WGPURenderPassDescriptor){
        .colorAttachmentCount = 1, .colorAttachments = &color,
    });

    g_active_pass.surface = s;
    return &g_active_pass;
}
void ne_renderer_end_frame(NERenderer *r, NERenderSurface *s) {
    wgpuRenderPassEncoderEnd(s->pass_encoder);

    WGPUCommandBuffer cmd = wgpuCommandEncoderFinish(s->encoder, NULL);
    wgpuQueueSubmit(r->queue, 1, &cmd);
    wgpuCommandBufferRelease(cmd);

    // Release everything for this frame
    wgpuRenderPassEncoderRelease(s->pass_encoder);
    wgpuCommandEncoderRelease(s->encoder);
    wgpuTextureViewRelease(s->view);
    wgpuTextureRelease(s->texture);

    // NO wgpuSurfacePresent() call — the browser presents when
    // control returns to it (via requestAnimationFrame).
    g_active_pass.surface = NULL;
}
There's no explicit "present" step. When your main-loop callback returns, the browser draws your frame automatically and schedules the next requestAnimationFrame. This is why the WebGPU backend has no fence or semaphore — the browser handles frame pacing.

Shaders — WGSL only

WebGPU doesn't have a bytecode format. Every shader is source text in WGSL (WebGPU Shading Language).

// shaders/wgsl/basic.wgsl
struct VertexOut {
    @builtin(position) pos: vec4<f32>,
    @location(0) color: vec4<f32>,
};

@vertex
fn vs_main(@location(0) in_pos: vec2<f32>, @location(1) in_col: vec4<f32>) -> VertexOut {
    var out: VertexOut;
    out.pos = vec4<f32>(in_pos, 0.0, 1.0);
    out.color = in_col;
    return out;
}

@fragment
fn fs_main(in: VertexOut) -> @location(0) vec4<f32> {
    return in.color;
}
⚠️ ne_shader_create (bytecode) is a stub

On this backend, only ne_shader_create_from_source works. Passing SPIR-V bytecode logs an error and returns null. The comment in the code: "The browser has no portable shader-bytecode path — SPIR-V passthrough is not available in WebGPU."

The push-constant gap

WebGPU deliberately doesn't have push constants. Uniform data must go through a uniform buffer + bind group. The engine doesn't yet emulate this:

// From src/renderer/wgpu/ne_renderer_wgpu.c
void ne_render_pass_set_uniform_data(...) {
    NE_LOG_WARN("WebGPU has no push-constants / setBytes equivalent. "
                "Inline uniforms must go through a uniform buffer + bind group, "
                "which this backend does not yet implement.");
    // does nothing
}
The right fix

A ring-buffered uniform buffer that gets bound as a bind group per draw. Every frame, the CPU writes uniform data into a slice of the ring, and the shader indexes into it via a dynamic offset. Standard technique — just needs to be built.

Pipelines — eager, but format-gated

Compilation is synchronous once you call ne_pipeline_create. But there's a subtle rule: the surface format must be known first, which only happens on the first begin_frame call.

// From ne_pipeline_create
if (!r->device_ready) return (NEPipelineHandle){0};
if (r->surface_format == WGPUTextureFormat_Undefined) {
    NE_LOG_WARN("pipeline create before first begin_frame — format unknown");
    return (NEPipelineHandle){0};
}
⚠️ Pipeline-create ordering trap

Apps must call begin_frame at least once (may return null, that's fine) before creating any pipelines. The demo works around this because pipelines are created after the first frame has begun.

The web platform layer

The web build compiles your C code to WebAssembly (WASM) via Emscripten. The engine still needs to translate DOM events into NEKey/mouse coordinates:

// src/platform/web/window_web.c
static const char *NE_WEB_CANVAS_TARGET = "#canvas";

void ne_app_run(NEApp *app) {
    // Hand control to the browser
    emscripten_set_main_loop_arg(
        ne_web_frame_tick,   // called on every rAF
        app,
        /* fps = */ 0,       // 0 = use rAF instead of fixed FPS
        /* simulate_infinite_loop = */ 1
    );
    // main() unwinds here, but rAF keeps calling ne_web_frame_tick
}

static void ne_web_frame_tick(void *user) {
    NEApp *app = user;
    for (NEWindow *w = app->windows; w; w = w->next) {
        if (w->open && w->render_frame) w->render_frame(w->render_frame_user);
    }
}
⚠️ Stack lifetime gotcha

Because main() returns while requestAnimationFrame keeps firing, any state the render callback touches must not live on main()'s stack. Put it in globals, or on the heap. The engine's built to avoid this — the frame context in main.c is a stack local, which technically works but only because Emscripten's -sEXIT_RUNTIME=0 keeps the WASM heap alive.

Event translation

DOM events use string codes like "KeyA", "ArrowUp". The web layer maps them to NEKey:

static NEKey ne_web_map_key(const char *code) {
    if (strlen(code) == 4 && strncmp(code, "Key", 3) == 0)
        return NE_KEY_A + (code[3] - 'A');
    if (strlen(code) == 6 && strncmp(code, "Digit", 5) == 0)
        return NE_KEY_0 + (code[5] - '0');
    if (strcmp(code, "Escape") == 0)   return NE_KEY_ESCAPE;
    if (strcmp(code, "ArrowLeft") == 0) return NE_KEY_LEFT;
    // ...
}

Mouse buttons follow DOM order (0=left, 1=middle, 2=right) — this differs from macOS's Cocoa ordering (0=left, 1=right, 2=middle). The engine keeps them separate.

How this could be better
  • Emulate push constants. The biggest functional gap. A ring uniform buffer + bind group would fix it.
  • Textures. WebGPU has full image/texture support — nothing wired up.
  • Startup ordering. The device-not-ready and format-not-set race conditions surface too aggressively. A queue of "setup work to run once ready" would smooth this over.
  • Multi-surface. The g_active_pass global is the last barrier to multi-window on the web.
  • Cross-compile shaders. Every backend has its own shader language. Slang or Tint (WGSL) could bridge.
